# CLD-UF-101 Module Knowledge Checks

These checks are formative. They reinforce learning after each self-paced module.

---

## Module 1 — Introduction to Claude

### Questions

1. Claude is best described as:
   - A. A traditional search engine
   - B. An AI assistant that can help with language, reasoning, and document tasks
   - C. A spreadsheet tool only
   - D. A password manager

2. Why should high-stakes Claude output be verified?
   - A. Claude cannot produce polished writing
   - B. Claude can sound confident even when wrong
   - C. Claude only works with images
   - D. Verification is never needed

3. Give two examples of things Claude can help with.

4. Give two examples of output that should be checked before use.

### Answers

1. B
2. B
3. Examples: drafting, summarizing, brainstorming, analysis, explanation, document review.
4. Examples: names, dates, numbers, quotes, citations, legal/compliance wording, financial figures, customer claims.

   - A. Only one word

## Module 3 — Core Use Cases

### Questions

1. Match the task to the use case:
   - Draft an email
   - Extract action items
   - Generate 10 campaign ideas
   - Compare three vendor options
   - Explain a technical term to a manager

2. Which use case is best for generating options?
   - A. Brainstorming
   - B. File storage
   - C. Password reset
   - D. Calendar sync

3. Why should the first output often be treated as a draft?

### Answers

1. Writing/editing; summarization; brainstorming; analysis; ask/explain.
2. A
3. The first response may need more context, tone adjustment, fact-checking, or format refinement.

## Module 4 — Effective Prompting

### Questions

1. A strong prompt often includes audience, context, task, tone, constraints, and format.
   - True
   - False

2. What is the main problem with this prompt: “Write something about training”?

3. When should you ask Claude to ask clarifying questions?

4. Give one useful follow-up prompt.

### Answers

1. True
2. It is vague and does not specify purpose, audience, context, tone, format, or required details.
3. When the task is complex, ambiguous, or missing important requirements.
4. Examples: “Make it shorter,” “Add a call to action,” “Turn it into a table,” “Ask me what you need before drafting.”

## Module 5 — Working with Documents and Files

### Questions

1. Before uploading a file, what should you check?

2. Name three things Claude can help do with a document.

3. Why should spreadsheet analysis be verified?

4. What are Artifacts useful for?

### Answers

1. Whether the file is allowed, whether it contains sensitive data, and whether the organization permits the use case.
2. Summarize, extract action items, find gaps, create checklists, compare, rewrite, structure into tables.
3. Calculations, source data, and interpretations may be wrong or incomplete.
4. Substantial reusable outputs such as documents, tables, checklists, drafts, plans, or code.

## Module 6 — Projects and Memory

### Questions

1. A Project is useful for:
   - A. Repeated work with shared context
   - B. Erasing every conversation
   - C. Password storage
   - D. Replacing human review

2. What are custom instructions or styles useful for?

3. Why should Memory be managed carefully?

4. Name one thing you should not store in a Project or Memory.

### Answers

1. A
2. Applying repeated preferences such as tone, format, response style, or default rules.
3. It may retain context across conversations and should not store sensitive or unnecessary information.
4. Passwords, secrets, confidential data, customer personal data, legal privileged material, regulated data.

## Module 7 — Best Practices and Pitfalls

### Questions

1. What does “confidently wrong” mean?

2. Which output should receive the most verification?
   - A. A list of brainstorming ideas
   - B. A rough internal note
   - C. A client-facing proposal with pricing and commitments
   - D. A practice sentence

3. Name five things you should verify.

4. What should you do if you are unsure whether data is safe to enter?

### Answers

1. Claude can state incorrect information fluently and confidently.
2. C
3. Names, dates, numbers, quotes, citations, legal/compliance language, financial figures, customer claims, technical steps.
4. Do not enter it until you have checked organizational policy or received approval.

## Module 8 — Capstone

### Questions

1. What must a capstone submission include?

2. Why is iteration required?

3. What must be included in the verification list?

### Answers

1. Task description, use case, initial prompt, output summary, follow-up prompt, improved output summary, verification list, and workplace application.
2. It demonstrates the learner can refine and improve Claude output rather than accepting the first draft blindly.
3. Any names, dates, numbers, claims, assumptions, sensitive data, source references, or expert-review items that must be checked before use.
