Purchasing and access model

The page is prepared for payment-provider checkout and subscription-driven access control.

1. Payment checkout

Replace each plan button with a hosted checkout link from Stripe, PayFast, Yoco, Peach Payments, Paystack or Paddle. Until then, the buttons open a purchase email for invoice-based activation.

2. Subscription webhook

On payment success, your backend should receive checkout, invoice paid, failed payment, cancellation and plan-change webhooks and write the learner entitlement to the user profile.

3. RBAC enforcement

Map subscription status to roles such as free_user, starter, pro, mentor and team_member. Course access, AI quotas, certificates and reporting should be checked server-side.

Implementation note: the visible buttons currently use invoice/request links so the page is safe to publish immediately. For live card payments, replace the button href values with production checkout URLs and preserve the data-plan attributes for analytics and RBAC mapping.
